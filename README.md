# 剧本演绎 App - 项目文档（整理版）

## 1. 项目简介
这是一款基于 Flutter 的剧本演绎 App，**适配 iOS/Android 双端**。用户可选择不同剧本与角色进行沉浸式角色扮演。App 提供丰富的剧本类型与角色选择，支持快速匹配与历史记录，旨在提升互动娱乐体验。

## 2. 目标平台与版本范围
- **目标平台**：iOS / Android（Flutter 双端适配）
- **版本阶段**：MVP 1.0
- **定位**：沉浸式多人/单人角色扮演与剧情互动

## 4. 核心功能模块

### 4.1 用户体系（基础支撑）
- **第三方登录**：支持 Apple ID（Sign in with Apple）、Google、Facebook 一键登录
- **邮箱登录**：支持邮箱 + 密码注册/登录
- **游客模式**：允许游客体验，后续可绑定账号
- **账号绑定**：游客账号可绑定邮箱/手机号/第三方账号

### 4.2 首页
#### 4.2.1 剧本分类页（Script）
- **剧本列表**：推荐剧本（封面、名称、类型、时长）
- **可玩剧本**：用户可参与的剧本（封面、名称、类型、时长）

#### 4.2.2 角色分类页（Characters）
- **角色分类**：主角/反派/配角/群演
- **角色信息**：头像、名称、特点标签（如：侠客、学霸、校草）

### 4.3 剧本详情模块
- **基本信息**：简介、角色列表、难度
- **角色选择**：选择可扮演角色
- **剧本评论**：仅支持剧本一级评论（无回复/点赞），保留举报入口

### 4.4 角色详情页面
- **基本信息**：头像、名字、特点标签、难易程度、标志性台词
- **性格/特点标签**：详细标签描述
- **人物背景描述**：背景故事与相关信息
- **演绎雷达图**：演技、逻辑、沉浸、感情、节奏等维度
- **主要人物关系**：人物关系网络

### 4.5 剧场（快速匹配）
- **匹配入口**：首页一键启动（仅匹配“角色”）
- **偏好优先**：优先匹配注册偏好；无偏好则随机匹配角色
- **分类策略（MVP）**：为避免内容稀缺导致失败，MVP 不提供匹配分类设置
- **匹配结果**：展示角色详情、剧本片段
- **重新匹配**：用户关闭角色信息后可重新匹配
- **退出匹配**：匹配过程中退出则停止匹配流程
- **匹配超时策略**：匹配超过 10 秒未返回结果，则自动切换为随机匹配并提示用户
- **重复角色去重权重**：对最近 24 小时已匹配过的角色降低权重，优先匹配未出现角色

### 4.6 历史记录
- **游戏记录**：时间、剧本封面、名称、角色、进度/结局
- **未完成剧本**：继续游戏（从存档点恢复）
- **重新开始**：支持重开已玩剧本
- **分享记录**：结局分享到外部社交平台（可选）
- **角色招募列表**：用户发布组队信息（MVP 低优先级，可能删除）

### 4.7 个人中心
- **个人资料**：头像、昵称、ID 展示与编辑
- **剧本创作中心入口**：MVP 仅做预热 Banner
- **偏好设置**：剧本类型与角色类型偏好
- **游戏统计**：总游戏时长、完成剧本数、解锁结局数
- **基础设置**：通知开关、隐私设置（简版）
- **帮助反馈**：帮助文档与反馈入口

### 4.8 消息系统
- **平台信息推送**：标题栏入口，接收系统通知/活动信息
- **用户私信（IM）**：不建立好友关系，仅会话模式
- **剧本邀请/组队成功消息**：支持邀请与组队成功通知
- **红点提示**：未读消息数量提示
- **推送卡片**：顶部信息提示卡
- **推送卡操作**：
  - 点击进入信息列表
  - 点击关闭按钮
  - 超时自动消失
- **红点持久**：用户查看前持续提示
- **私信能力范围**：
  - 基础功能：文字、图片、emoji
  - 付费/VIP 功能：语音通话、视频通话

### 4.9 详情页面入口
- **剧本详情入口**：剧本卡片点击进入
- **角色详情入口**：角色卡片点击进入

## 5. 技术实现（Flutter）

### 5.1 前端技术栈
- **Flutter**：跨端 UI 框架
- **Dart**：主要开发语言
- **Material / Cupertino**：双端设计风格适配
- **Flutter 布局体系**：Row/Column/Stack 等组件布局

### 5.2 核心功能实现
#### 轮播功能
- 使用 PageView/AnimatedSwitcher 实现卡片轮播
- 自动播放，每张停留 5 秒
- 指示器显示当前卡片位置

#### 卡片布局
- 响应式卡片设计
- 卡片包含封面、名称、类型标签、时长信息
- 支持横向滚动列表（ListView/SingleChildScrollView）

#### 双端优化
- 统一触摸体验与交互手势
- 适配 iOS/Android 屏幕尺寸与设计规范
- 处理平台差异（字体、返回手势、权限提示）

## 6. 使用指南（Flutter）

### 6.1 安装与启动
1. 安装 Flutter SDK 并配置环境变量
2. 执行 `flutter pub get` 安装依赖
3. 运行 `flutter run` 启动 iOS/Android 应用

### 6.2 主要操作流程
1. **浏览剧本**：首页浏览推荐/可玩剧本
2. **选择角色**：进入角色分类页选择角色
3. **查看详情**：点击剧本或角色查看详情
4. **快速匹配**：一键匹配进入剧场
5. **查看历史**：历史记录中查看已玩/未完成
6. **个人设置**：编辑资料与偏好

## 8. 开发注意事项

### 8.1 双端适配
- 交互元素适合触摸操作
- 字体大小与间距可读性优化
- 适配不同 iOS/Android 设备屏幕

### 8.2 性能优化
- 图片加载与缓存优化
- 减少 DOM 操作，提升响应速度
- 轮播与滚动保持流畅

### 8.3 用户体验
- 简化注册登录流程
- 清晰导航与操作指引
- 明确错误提示与状态反馈

### 8.4 举报流程
- **入口**：剧本评论/私信消息/用户资料页均提供举报入口
- **步骤**：选择原因 → 补充说明/证据 → 提交 → 系统回执
- **处理时效**：普通举报 24-48 小时内处理，严重违规优先处理
- **结果通知**：站内通知反馈处理结果，支持用户申诉

### 8.5 违规处理规则
- **轻度违规**（如轻微骚扰、低质刷屏）：内容删除 + 警告/短期禁言
- **中度违规**（如重复骚扰、引战辱骂）：内容删除 + 7-30 天禁言
- **严重违规**（如涉政暴恐、色情、诈骗）：内容删除 + 永久封禁
- **累犯处理**：多次违规按等级升级处罚；保留违规记录

### 8.6 VIP 权益与定价（示例）
- **基础功能**：文字/图片/emoji 私信（免费）
- **VIP 权益**：语音通话、视频通话（含赠送通话时长）
- **通话计费**：赠送时长耗尽后，语音/视频通话按分钟消耗内部货币
- **定价**：USD $4.99/月，$12.99/季，$39.99/年（含税与地区定价按应用商店规则调整）

### 8.7 内部货币（示例）
- **用途**：解锁剧本、特殊角色、视频/语音通话按分钟计费
- **购买方式**：支持单独购买，不依赖 VIP
- **与 VIP 的关系**：VIP 赠送通话时长；时长耗尽后使用内部货币继续通话
- **充值档位（示例）**：USD $0.99 / $4.99 / $9.99 / $19.99 / $49.99（对应货币数量随活动调整）
- **货币有效期**：自购买之日起 24 个月有效；赠送币有效期 6 个月
- **赠送币规则**：节日活动/新手礼包/连续登录可获得赠送币；赠送币优先消耗
- **促销折扣**：充值折扣、限时礼包、首充双倍等活动可变更币量或价格
- **退款规则**：
  - 未消耗货币可在购买后 14 天内申请退款（以应用商店政策为准）
  - 已消耗货币不支持退款
  - 违规封禁导致账户不可用的，余额不予退还

## 10. 发现的问题与漏洞

### 10.1 文档一致性与范围问题
1. **双端适配范围需明确**：已改为 Flutter 双端实现，但仍需明确最低系统版本、设备分辨率与差异化交互规范。
2. **构建与发布流程缺失**：缺少 Flutter 打包、签名、渠道发布流程说明（如 TestFlight/Google Play 内测）。
3. **环境与依赖说明不足**：未明确 Flutter SDK 版本、最低 iOS/Android 版本与依赖锁定策略。

### 10.2 需求缺失与风险点
1. **后端能力未描述**：登录、匹配、消息、历史记录等均需要服务端支持，但未说明接口、数据模型与同步策略。
2. **匹配数据稀缺风险**：MVP 角色量少导致重复是客观限制，兜底策略为提示“内容产出中”，并提供跳转首页选剧本路径，同时宣传下个版本核心能力：用户自创剧本。
3. **存档与进度机制缺失**：未明确存档频率、断线恢复、跨设备同步策略。
4. **剧本版权与内容来源不明**：未说明版权归属、审核流程与内容合规策略。

### 10.3 安全与合规漏洞
1. **三方登录与账号绑定安全**：未描述 Apple/Google/Facebook 的 OAuth 流程、Token 存储位置、账号合并与解绑规则，存在账号劫持/覆盖风险。
2. **UGC 风控缺失**：评论/私信/招募为用户生成内容，缺少审核、举报、屏蔽与黑名单机制。
3. **隐私与数据合规不足**：偏好标签、匹配记录、历史记录均为个人数据，缺少隐私政策、用户授权与数据保留说明。
4. **分享功能的权限与脱敏**：对外分享结局与记录可能涉及隐私或剧本剧透，需明确默认脱敏规则与用户确认流程。
5. **潜在内容注入风险**：若采用 Web 视图或富文本展示 UGC，需明确转义与过滤策略，避免 XSS/脚本注入。

### 10.4 运营与体验风险
1. **消息推送频控与打扰**：未说明推送频率与用户退订机制，易引发打扰投诉。
2. **新手引导缺失**：复杂玩法（匹配、角色演绎）缺少新手引导与教程规划。
3. **异常与空态处理缺失**：网络异常、无剧本/无角色/无匹配结果等空态未定义。
