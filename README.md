# 剧本演绎 App - 项目文档（整理版）

## 1. 项目简介
这是一款基于 iOS 平台的剧本演绎 App，**优先发布平台为 iOS 端**。用户可选择不同剧本与角色进行沉浸式角色扮演。App 提供丰富的剧本类型与角色选择，支持快速匹配与历史记录，旨在提升互动娱乐体验。

## 2. 目标平台与版本范围
- **首发平台**：iOS
- **版本阶段**：MVP 1.0
- **定位**：沉浸式多人/单人角色扮演与剧情互动

## 4. 核心功能模块

### 4.1 用户体系（基础支撑）
- **第三方登录**：支持 Apple ID（Sign in with Apple）、Google、Facebook 一键登录
- **邮箱登录**：支持邮箱 + 密码注册/登录
- **游客模式**：允许游客体验，后续可绑定账号
- **账号绑定**：游客账号可绑定邮箱/手机号/第三方账号

### 4.2 首页
#### 4.2.1 剧本分类页（Script）
- **剧本列表**：推荐剧本（封面、名称、类型、时长）
- **可玩剧本**：用户可参与的剧本（封面、名称、类型、时长）

#### 4.2.2 角色分类页（Characters）
- **角色分类**：主角/反派/配角/群演
- **角色信息**：头像、名称、特点标签（如：侠客、学霸、校草）

### 4.3 剧本详情模块
- **基本信息**：简介、角色列表、难度
- **角色选择**：选择可扮演角色
- **剧本评论**：讨论区与评论入口

### 4.4 角色详情页面
- **基本信息**：头像、名字、特点标签、难易程度、标志性台词
- **性格/特点标签**：详细标签描述
- **人物背景描述**：背景故事与相关信息
- **演绎雷达图**：演技、逻辑、沉浸、感情、节奏等维度
- **主要人物关系**：人物关系网络

### 4.5 剧场（快速匹配）
- **匹配入口**：首页一键启动
- **偏好匹配**：基于偏好标签匹配角色
- **匹配结果**：角色详情、剧本片段
- **快速进入**：进入剧本演绎场景

### 4.6 历史记录
- **游戏记录**：时间、剧本封面、名称、角色、进度/结局
- **未完成剧本**：继续游戏（从存档点恢复）
- **重新开始**：支持重开已玩剧本
- **分享记录**：结局分享到外部社交平台（可选）
- **角色招募列表**：用户发布组队信息（MVP 低优先级，可能删除）

### 4.7 个人中心
- **个人资料**：头像、昵称、ID 展示与编辑
- **剧本创作中心入口**：MVP 仅做预热 Banner
- **偏好设置**：剧本类型与角色类型偏好
- **游戏统计**：总游戏时长、完成剧本数、解锁结局数
- **基础设置**：通知开关、隐私设置（简版）
- **帮助反馈**：帮助文档与反馈入口

### 4.8 消息系统
- **平台信息推送**：标题栏入口，接收系统通知/活动信息
- **用户私信**：标题栏入口，支持私信交流
- **红点提示**：未读消息数量提示
- **推送卡片**：顶部信息提示卡
- **推送卡操作**：
  - 点击进入信息列表
  - 点击关闭按钮
  - 超时自动消失
- **红点持久**：用户查看前持续提示

### 4.9 详情页面入口
- **剧本详情入口**：剧本卡片点击进入
- **角色详情入口**：角色卡片点击进入

## 5. 技术实现（前端原型）

### 5.1 前端技术栈
- **HTML5**：页面结构
- **CSS3**：样式设计
- **JavaScript**：交互逻辑
- **Flexbox / Grid**：响应式布局

### 5.2 核心功能实现
#### 轮播功能
- 3 个卡片淡入淡出轮播
- 自动播放，每张停留 5 秒
- 指示器显示当前卡片位置

#### 卡片布局
- 响应式卡片设计
- 卡片包含封面、名称、类型标签、时长信息
- 支持横向滚动列表

#### iOS 优化
- 移除 hover 等 Web 交互
- 优化触摸体验
- 适配 iOS 屏幕尺寸与设计规范

## 6. 使用指南（原型）

### 6.1 安装与启动
1. 打开 `index.html` 启动原型
2. 或使用本地服务器：`http://localhost:8000/characters.html`

### 6.2 主要操作流程
1. **浏览剧本**：首页浏览推荐/可玩剧本
2. **选择角色**：进入角色分类页选择角色
3. **查看详情**：点击剧本或角色查看详情
4. **快速匹配**：一键匹配进入剧场
5. **查看历史**：历史记录中查看已玩/未完成
6. **个人设置**：编辑资料与偏好

## 10. 发现的问题与漏洞

### 10.1 文档一致性与范围问题
1. **平台与技术实现不一致**：文档强调 iOS 首发，但技术实现与目录结构为 H5/静态页面原型，需明确“原型”与“正式 iOS 客户端”的边界与计划。
2. **启动方式不匹配**：仅提供 `index.html`/`localhost` 启动方式，缺少 iOS 工程构建与调试流程说明。
3. **目录结构与实际工程不一致**：当前结构为静态 HTML 组件，不符合 iOS 或现代前端工程目录规范，建议补充真实项目结构说明。
4. **MVP 边界不清**：部分功能（消息系统/评论/私信）工作量大，但未标注是否纳入 MVP。

### 10.2 需求缺失与风险点
1. **后端能力未描述**：登录、匹配、消息、历史记录等均需要服务端支持，但未说明接口、数据模型与同步策略。
2. **匹配机制缺少兜底策略**：未说明匹配失败、排队超时、取消匹配等场景处理。
3. **存档与进度机制缺失**：未明确存档频率、断线恢复、跨设备同步策略。
4. **剧本版权与内容来源不明**：未说明版权归属、审核流程与内容合规策略。

### 10.3 安全与合规漏洞
1. **三方登录与账号绑定安全**：未描述 Apple/Google/Facebook 的 OAuth 流程、Token 存储位置、账号合并与解绑规则，存在账号劫持/覆盖风险。
2. **UGC 风控缺失**：评论/私信/招募为用户生成内容，缺少审核、举报、屏蔽与黑名单机制。
3. **隐私与数据合规不足**：偏好标签、匹配记录、历史记录均为个人数据，缺少隐私政策、用户授权与数据保留说明。
4. **分享功能的权限与脱敏**：对外分享结局与记录可能涉及隐私或剧本剧透，需明确默认脱敏规则与用户确认流程。
5. **潜在内容注入风险**：若采用 Web 视图或富文本展示 UGC，需明确转义与过滤策略，避免 XSS/脚本注入。

### 10.4 运营与体验风险
1. **消息推送频控与打扰**：未说明推送频率与用户退订机制，易引发打扰投诉。
2. **新手引导缺失**：复杂玩法（匹配、角色演绎）缺少新手引导与教程规划。
3. **异常与空态处理缺失**：网络异常、无剧本/无角色/无匹配结果等空态未定义。
